# Research log

Research must answer a specific question — not "browse the internet about
the topic." Log every finding that actually influenced a decision here, so
it survives past the chat session that produced it. If it's not here, it
didn't happen as far as the next agent is concerned.

**Status: empty.** Nothing to research yet — no problem statement. Once
one exists, `PLAYBOOK.md`'s Problem-Statement Mode calls for research into:
domain knowledge, existing products/competitors, technical alternatives,
relevant APIs/datasets/standards, security considerations, UX conventions,
and genuine Caterpillar relevance/differentiation angles.

## Format

| ID | Question | Source | Date | Finding | Relevance | Decision influenced |
|---|---|---|---|---|---|---|
| R-001 | *(example row — delete once real entries exist)* Does library X handle requirement Y out of the box? | official docs, [url] | 2026-09-01 | Yes, via config Z | High — avoids building it ourselves | `DECISIONS.md` entry on using X |

Keep entries short. A one-line finding beats a pasted article. If a finding
is long, summarize it here and link to a saved source, don't paste walls of
text.
